1. Executive verdict
The repository is a credible and unusually well-audited numerical engineering proof of
concept. It is not yet a validated model of CPRI's actual impulse generator. The recommended
competition verdict is READY WITH CONDITIONS for an offline numerical demonstration; NOT
READY for operational hardware instructions or claims of measured CPRI accuracy.
The strongest route to a competitive submission is to preserve its engineering core, resolve or expose the
few physical assumptions that determine whether its recommendations are buildable, make the existing
decision process faster and easier to understand, and demonstrate a useful response to a failed test.
Adding an untrained measured-residual layer, another model family, or learned catalog pruning would
not currently supply new physical information. These conclusions come from the pinned source, primary
challenge material, independently reproduced calculations and current engineering literature, rather
than from the repository's own readiness verdict. [R01–R20]
The central corrections to the team's understanding
First, this snapshot is newer than the architecture summary in the request. The default search is already
504 candidates for one impulse type and fixed topology, expanding to 588 when an explicit LI parallel-tail
hypothesis is enabled. The physics solver already uses a guarded modal method. The four selected ML
models already perform residual learning—but the residual is from an analytic zero-inductance RC
approximation to the team's finite-inductance RLC simulator. It is not the difference between simulation
and measured CPRI shots. A separate batch ML exploration route also exists. [R09, R11–R14]
Second, the broad statement that final recommendations are physics-led is correct. The optimizer
evaluates every declared candidate, determines charge from physics gain, evaluates the selected charge
through the forward stack, and ranks the physics waveform's conformity. ML estimates and disagreement
are retained, but ML neither prunes the catalog nor overrides the result. This is defensible at the current
scale. One archived LI request contains a sole physics-passing candidate that a hard ML-pass filter would
discard. That is a concrete counterexample to treating present surrogate pruning as harmless. [R13, R14,
R19]
Third, the primary weakness is model identification, not an exposed ODE sign error. The October 4 CPRI
response confirms six actual resistor values. It does not establish all quantities, placements, fired branch
states, a complete permissible connection catalog, or the optional 180 Ω parallel 520 Ω tail arrangement.
All approved recipes remain absent from the profile. Exhaustive enumeration of a provisional catalog is
not exhaustive proof about the real laboratory machine. [R04, R08, R14]
Fourth, there are actionable software defects. Imported measurement evidence is omitted from the
advertised complete export bundle. UI wording can misdescribe an empty inventory or a crest-limited
no-solution result, and the displayed hardware-change count differs from the ranking definition.
Exact-byte provenance also has a reproducible cross-platform newline problem: some recorded hashes
require CRLF while other source hashes require LF. This can break a fresh checkout without proving that
the separately packaged Windows release is broken. [R15–R18, R20]

The three fresh recommendation runs took 11.22, 11.79 and 12.34 seconds in the Linux audit
environment using the supported physics fallback with an intentionally absent model registry. These are
not production Windows, ML-enabled end-to-end timings. A direct 504-trajectory physics batch took 3.72
seconds. The source also shows repeated all-model hashing inside each candidate call, potentially
traversing approximately 94.45 GB of model bytes for a cold 504-candidate, two-call search. This is
evidence for optimizing execution overhead before using approximation to shrink the search. [R14, R20]
The single recommended architectural decision
Use complete declared-catalog evaluation with an evidence-gated predictor: nominal physics
today; calibrated physics when identifiable measured evidence exists; a small empirical
residual only if it improves independent decision outcomes beyond calibrated physics. Solve
charging voltage against that same active predictor. Retain the existing simulator surrogate for batch
exploration and explicitly labeled comparison. Keep physical limits, waveform qualification, prediction
evidence and operator approval separate.
This is a refinement of the proposed physics-plus-residual design. It prevents calibration from hiding a
wrong circuit, prevents charge from becoming inconsistent with a corrected crest, and avoids inventing
uncertainty percentages. It also creates a practical progression from useful software today to a genuinely
calibrated laboratory tool later. It does not require adding a flexible residual model before the finale.
What is most likely to improve competition value
The highest-value work is: establish the real connection/operating definition or scope its uncertainty
precisely; freeze and rehearse the exact offline build; remove repeated verification and serialization
overhead without weakening integrity; explain the next legal change using the already evaluated
catalog; and complete the measured-comparison evidence loop. A small fixed-setting sensitivity
comparison is worthwhile after these are secure. A low-voltage physical demonstration is optional and
worthwhile only if suitable instruments and a repeatable fixture already exist.
A simpler competing team could beat this project by using the correct physical arrangement, producing a
validated first-shot setting, and explaining it clearly. Conversely, this project's careful source hierarchy,
negative cases, complete search and traceable decisions can be a substantial advantage if they are
demonstrated as useful engineering rather than a tour of internal machinery. No public participant
solutions or numerical judging weights were available; competitive comparisons in this report are
reasoned scenarios, not claims about actual competitors.

2. Reconstructed Track 1 requirements
What CPRI asked teams to build
The original problem asks for an intelligent software proof of concept that combines engineering
calculations with trained ML to recommend impulse-generator settings before physical testing. The
practical problem is repeated setup changes and trial runs as DUT capacitance, divider capacitance, stray
effects and physical arrangement vary. It is a recommendation and decision-support task for an engineer.
It does not specify autonomous firing, a particular model family, a stochastic optimizer, or ML authority
over final ranking. A web interface is preferred; later clarification explicitly permits offline operation. [R01
pp.1–4; R03]
The four required functional elements are an engineering calculation module, an ML engine learning
settings/load-to-waveform relationships, a recommendation engine ranking appropriate settings, and a
visualization dashboard. Required decisions are active stage count, charging voltage per stage, front
resistance and tail resistance. Required outputs include crest, waveform timing, deviations, conformity
indications, alternative rankings and target-versus-predicted waveforms. A reliable starting point for
actual laboratory trials is the intended engineering outcome. [R01 pp.1–3]
The original guidance says teams may generate or use supplied data, perform EDA and compare
algorithms. These are suggested methods, not mandates to deploy many algorithms. The later CPRI
discussion and supplied workbook support residual-learning experimentation, but do not require a neural
network, a learned inverse map, or a measured residual without measurements. [R01 p.3; R03; R05; R06]

Waveform profile and authority of tolerances
The challenge uses LI 1.2/50 µs and SI 250/2500 µs. October 1 explicitly gives LI front ±30% and tail

The competition's explicit 250 µs time-to-peak target should remain a versioned competition profile
unless CPRI directs otherwise. Avoid saying merely “IEC compliant”: a profile-consistent simulated scalar
check, a qualified measured-waveform evaluation, and apparatus certification are different claims.

What measured-data support is actually required to accomplish
The original PS emphasizes actual measured waveforms from different objects/configurations for
calibration and validation. The October 1 clarification makes provision conditional on data being available
and allows later import. Therefore no genuine shots means real accuracy remains unvalidated; it does
not automatically disqualify an otherwise useful software PoC. Importing measurements is a useful first
step, but it is not equivalent to fitting, validating or promoting a calibration. [R01 p.4; R03 lines 205–209]

4. Current repository architecture
The real request-to-result path
The application accepts an engineering request and setup, validates its domain, and creates a catalog for
one fixed impulse mode and one fixed topology hypothesis. It filters confirmed resistor values by user
availability and enabled recipe IDs. The default recipe allocates uniform single front and tail values across
stages. An optional, disabled-by-default LI/GSHUNT recipe uses separate 180 and 520 Ω tail parts in
parallel. [R14: catalog.py]
For every entry, the optimizer computes the legal charge interval from known voltage and energy
ratings. It calls the full prediction stack at the highest legal reference charge, obtains the physical crest
gain, solves the charge needed for the target and tolerance band, then calls the stack at the chosen
actual charge or legal neighboring discrete charges. The current implementation repeats the waveform
simulation even where linear amplitude scaling could reuse the same shape. [R14: charge.py; service.py
lines 25–106]
The forward stack executes the finite-L circuit solver and waveform evaluator. It also attempts to load the
appropriate trained model, constructs analytic features, checks provenance and support, and supplies ML
scalar estimates when permitted. A field named selected_prediction can refer to ML inside this forward
API. That field does not determine the optimizer's ranking: the optimizer explicitly scores
physics_reference metrics, stores an independent ML score, and records disagreement. [R13:
inference.py; R14: service.py]
All candidate rows are sorted by numerical admissibility/conformity, normalized waveform error J,
margin, hardware-field changes, energy, stage count, part values and stable ID. Only a passing row can
become best_configuration. A closest noncompliant result is separately labeled. The saved result includes
the exact request, catalog, candidate results, settings, source/model fingerprints, waveform artifacts and
history identity. [R14]

What the current residual learns
For each route, an exact analytic zero-inductance RC calculation supplies baseline gain and times. The
selected learner predicts log(target / baseline), where the target is produced by the finite-inductance
simulator. Exponentiating and multiplying by the baseline produces positive scalar estimates. This is a
legitimate physics-guided residual formulation. It learns missing inductive behavior relative to the
simplified analytic baseline under the declared circuit; it cannot discover discrepancies absent from its
simulator labels. [R11–R13]
The current separate batch-screening route is meaningful: it can evaluate 1–4,096 explicitly supplied
scenarios using analytic features and the model, without running every full waveform. Its output is
labeled ML_SCREEN_ONLY, with support/abstention information. It is suitable for quick exploration or
cross-checking. It does not certify a waveform, prove a valid connection, or define a reduced optimizer
catalog. [R13: screening.py]
Architecture assessment
The existing architecture has the correct safety of decision scope for the available evidence: cheap
complete physics evaluation is the final numerical reference; ML is useful but bounded. The main
inefficiency is invoking that entire guarded stack repeatedly for each candidate, including repeated
artifact hashing and scalar model work that cannot change the final recommendation. The main scientific
limitation is that the physical model remains provisional. Refactoring authority without new evidence
cannot resolve that limitation.
The application already has many elements the proposed redesign might otherwise re-create: source
labels, setup provenance, numerical-versus-hardware status, waveform plots, alternatives, an explicit
no-solution scope, ML disagreement, saved histories, a scenario screen and import diagnostics. Preserve
them. Improve their visibility and consistency rather than replacing a mature flow with an elaborate new
diagram.

6. Physics audit
Verdict and exact model scope
The declared passive circuit implementation is scientifically coherent and numerically well
verified. Its correspondence to the real CPRI generator is unestablished. It represents an ideally
erected equal-stage source, lumped front-path resistance and inductance, a capacitive output load, one
of two tail-resistor locations, and optional output leakage. It does not identify the actual fired graph from
measurements or model every spark gap, intermediate node, divider transfer function or distributed lead.
[R08–R10]
This is an appropriate baseline for a PoC if its scope is visible. It can also become an appropriate baseline
for calibration after the physical graph and dominant effective parameters are constrained. A residual
model cannot make an incorrect graph physically identified merely by reducing a scalar fitting error.

Equal-stage reduction and energy
For N identical stages, stage capacitance Cs and equal per-stage charge voltage q, the model uses Cg =
Cs/N, initial erected voltage U0 = Nq, Rf = Nrf + Rloop, and Rt = Nrt. The lower-case rf and rt are
per-stage recipe equivalents. In the optional tail recipe, rt = (1/180 + 1/520)⁻¹ = 133.7142857 Ω. That
equivalent is derived from two distinct physical parts; it is not a seventh supplied resistor. [R09:
engine.py, recipes.py]
The energy identity is E0 = ½ Cg U0² = ½ N Cs q². With Cs = 0.5 µF, q = 200 kV and N = 15, the result is
exactly 150 kJ; per stage it is 10 kJ. At N < 15, lower total energy follows automatically from the same
individual stage limit. These facts were independently checked. They are electrical stored-energy
constraints, not sufficient resistor pulse-rating or insulation-stress calculations. [R02–R03; R20]
The full-stage reference fixture separately stamps a uniform chain and compares its output with the
reduced graph, including explicit parallel tail branches at multiple stage counts. This is a useful reduction
proof under identical capacitors, equal initial voltages, simultaneous erection and no intermediate
stage-to-ground parasitics. It does not establish that CPRI actually uses that resistor allocation or that all
stages erect ideally. [R09: reference_cases.py; R10 tests]

• L · di/dt = vg − vo − Rf i.

For L = 0, current becomes i = (vg − vo)/Rf. The implementation creates the true resistive reduction
rather than hiding a small artificial inductance. For no load leakage, let the positive decay rates be α < β.
The output is:
vo(t) = U0 · [exp(−αt) − exp(−βt)] / [Rf CL (β − α)].
The characteristic coefficient b = 1/(Rf Rt Cg CL). For GSHUNT, a = 1/(Rt Cg) + 1/(Rf Cg) + 1/(Rf CL). For
OSHUNT, a = 1/(Rf Cg) + 1/(Rf CL) + 1/(Rt CL). Computing α = b/β avoids subtractive cancellation in the
slower decay rate when the rates are widely separated. These are correct expressions for the specified
two RC networks; they are not a universal formula for any Marx connection. [R09: analytic.py; W07]
Passivity, numerics and trajectory evaluation
For GSHUNT, dE/dt = −vg²/Rt − Rf i² − vo²/Rload ≤ 0. For OSHUNT, the tail-loss term uses vo²/Rt. The
network's energy scaling, algebraic elimination and dissipativity checks are technically sound. Singular or
ill-conditioned algebraic networks are rejected rather than silently repaired. Integrated dissipation and
remaining storage are checked against the initialized energy. A wrong but passive topology can still pass
every one of these checks. [R09: network.py, engine.py]
The current solver is modal, with guards and an implicit Radau route for comparison/fallback. Stationary
points and fractional crossings are inserted from the continuous trajectory before shared evaluation.

audit replayed 19 saved labels, including high-error ML examples and threshold cases; gain and timing

7. ML and data audit
What exists, and what its metrics can prove
The project has substantive ML engineering: route-specific models, direct/guided/residual formulations,
multiple algorithms, grouped split logic, shifted-domain tests, saved prediction arrays, model cards,
runtime/provenance guards, OOD checks and abstention. The four selected models are residual Extra
Trees. The available evidence supports their ability to approximate the declared finite-L simulator over
held-out input families. It does not establish real CPRI accuracy, learned hardware feasibility, calibrated
uncertainty, or fewer physical trial shots. [R11–R13]
There are three different data domains, and they must remain separate: the organizer workbook's
synthetic Observed values; the project's finite-L simulator labels using later-confirmed ratings; and future
genuine measured shots. Combining them without domain identity would manufacture evidence. No
genuine CPRI waveform shots were found in the acquired material. The supplied example import is
explicitly synthetic, and current imported records cannot be promoted to calibration eligibility. [R06, R12,
R16]
Complete workbook audit
All six sheets and cells were traversed: Hybrid Calculator, Resistor Inventory, Synthetic Dataset, ML
Helper, Model Validation and Model Card. All 7,029 formulas were checked by families and copy
consistency. The 2,000 synthetic rows comprise 1,000 LI and 1,000 SI, each with 700 training, 150
validation and 150 hidden-test rows. Cached formula results were present. The workbook itself discloses
that laboratory trial shots are pending. [R06; R20]
The workbook assumes 3 µF per stage, six times the later-confirmed 0.5 µF. Its tail formula independently
implies that same 3 µF across the entire dataset. Physics_Crest_kV equals the requested test voltage

uses 1.67 times the square root of a resistive term plus an inductive term; its application to SI is part of

Features, targets and algorithm choices
The guided/residual representation has 22 features: recipe indicator, N, front/tail values, separate
declared capacitances, loop L/R, reduced Cg/CL/Rf/Rt, dimensionless ratios/time scales, a zero-L indicator
and the independent analytic baseline outputs. Targets are gain, mode-specific front/peak time and tail
time. Crest is reconstructed as gain × N × charge. Requested crest, charge, polarity, row identity,
outcome status and observed labels are excluded from simulation features. That avoids obvious label
leakage and respects the declared linear amplitude symmetry. [R11]
The three algorithms are kNN with seven inverse-distance neighbors; Extra Trees with 128 trees and
minimum leaf two; and histogram gradient boosting with 180 iterations, 15 leaves, minimum leaf ten and
regularization one. Each has direct, physics-guided and residual formulations. Feature and target
transforms fit on training rows only. Residual models learn a log ratio against the analytic baseline,
preserving positive scalar predictions. Positive scalars alone do not guarantee a realizable or qualified
waveform. [R11: models.py]
The analytic baseline is independently computed with L = 0. It is not a disguised call to the target finite-L
simulator. The selected learner consequently corrects an approximate physics model toward a more
complete but still declared simulation. It does not add new laboratory information.

Current OOD combines feature bounds, transformed nearest-neighbor distance and seen discrete
stage/front/tail/parallel values. The distance radius is 1.5 times the training nearest-neighbor-distance

range, and an unsupported DUT cannot become valid merely by entering a capacitance value. [R11–R13]
The validation P95 envelopes are empirical approximation-error summaries after model selection. The
grouped bootstrap estimates uncertainty in average loss. Neither is a calibrated per-shot prediction
interval for the CPRI machine. Tree spread, distance to training data and simulator error do not jointly
account for topology, instruments, component tolerances or real-shot variation.

genuinely unseen parallel rows are OOD; the larger 1,539-row test set includes grouped single-tail
controls. These are useful abstention experiments. They should not be advertised as successful
supported extrapolation.

8. Optimizer audit
Candidate space and completeness
For one fixed LI/SI mode and one fixed GSHUNT/OSHUNT hypothesis, the default catalog has 14 stage
counts from two through 15, six front values and six tail values: 14 × 6 × 6 = 504 entries. The optional
LI/GSHUNT parallel-tail recipe adds 14 × 6 = 84 entries, making 588 when both recipe families are
enabled. Availability and explicit recipe restrictions reduce those counts. Approved scope contains zero
entries. [R14: catalog.py; R20]
The request fixes topology and setup. The optimizer does not quietly change DUT capacitance or L until a
passing waveform appears, does not optimize a different impulse type, and does not select whichever
graph yields a better score. These are strengths. The completeness claim must nevertheless be “all
entries in the declared catalog,” because nonuniform stage arrangements, additional branches,
quantities and approved connection possibilities have not been fully established.
The value inventory is discrete and well enforced. The connection inventory is provisional. This distinction
prevents two opposite errors: criticizing the software for ignoring the six values when it uses all six, and
praising it for a physically complete machine search when it has no approved BOM allocations.
Charging voltage
For fixed linear candidate and setup, crest V = kq, where k is obtained from the physical waveform at a
reference charge. The unconstrained exact choice is q* = Vtarget/k. The legal upper bound accounts for
stage voltage, summed voltage, per-stage energy and total stored energy. The implementation checks
the entire accepted crest band, clips to limits, and tests legal neighboring charges if a discrete grid is
supplied. Thus failure to reach the exact center does not imply failure to enter tolerance. [R14:
charge.py; service.py]
The minimum reliable charge and actual increment are unknown. The current continuous assumption is
explicit, and operator_ready remains false. An illustrative 50 kV request can require a per-stage charge
around 8.1 kV under the model; that does not establish reliable spark-gap firing at that charge. Practical
deployment requires minimum charge, resolution, tolerance and relevant duty/placement limits.
Five hundred independent randomized finite charge-grid comparisons confirmed that the
implementation's selected candidate charges attain the minimum crest error on the corresponding
explicit grids. Additional assertions checked limiting-band behavior, empty domains, catalog uniqueness
and availability. These are independent custom checks, not inflated counts of repository-native tests.
[R20]
Hard constraints, conformity and score
Known stage/total voltage and energy limits are hard constraints. Waveform validity and individual
crest/front/tail checks precede ranking. Unknown physical constraints remain unknown rather than
automatically becoming explicit failures, which permits conditional numerical results while keeping
hardware approval false. This is acceptable if the UI makes that conditional status unmistakable.

Research findings that materially change the decision
The most relevant HV paper located estimates load capacitance and stray inductance in
lightning-impulse circuits using numerical and experimental evidence. Its importance here is the
identifiable physical inverse problem, not its choice of a genetic algorithm. The generator's C/L mismatch
is a plausible source of systematic error that a bounded fit can address more coherently than an
unconstrained scalar residual. The actual CPRI graph and measurement plane still have to be known.
[W09]
Published hybrid modeling long predates this competition and includes learning unmeasured physical
parameters within first-principles models. Therefore “hybrid” need not mean putting a neural network
after every solver call. Learning a small parameter relationship, correcting reproducible discrepancy, or
supporting an efficient validated forward surrogate can all be legitimate roles when their data and benefit
are explicit. [W20]
The calibration literature supplies a warning: a flexible residual can compensate for wrong parameters,
and fitted parameters need not be physically true. That strengthens the case for bounded,
low-dimensional calibration and held-out configurations. It also argues against reporting a precise
inferred stray capacitance if several combinations of C, L, scale and timing offset explain the same trace.
[W15]
Commercial HV software already provides polished measurement, analysis, history and reporting. Track 1
value should be demonstrated in the transition from a requested test to an allowed setting, and from an
observed mismatch to a justified next change. The novelty claim should be a useful integrated
engineering workflow with defensible evidence, not “first waveform dashboard” or “first digital twin.”

Impulse-generator inverse design and learned resistor selection already appear in primary literature,
including work for low-inductance loads with different compensation circuits. Those results demonstrate
that simulation-assisted learning and experimental comparison are feasible. They do not justify
transferring a different circuit or load class into an insulator-focused CPRI model. [W14]
Methods that are genuinely compatible with the data
For the current synthetic corpus, a small tree ensemble or analytic residual is sensible. The existing
grouped protocol is better than a random row split because many rows share the same normalized
physics. More algorithm families are unlikely to resolve the physical uncertainty.
For a small genuine measured dataset, parameter calibration, regularized log-ratio corrections and
possibly a small Gaussian process are more data-efficient starting points than a deep network. A GP
provides a structured interpolation model with posterior uncertainty conditional on its assumptions; it
does not certify an unmeasured machine or resolve a wrong topology. Dimensional controls such as
CL/Cg, Rf/Rt and L/(Rf²Ceq) can reduce redundant representations, but their sufficiency must be checked
for the actual domain. [W18; engineering design recommendation]
For discrete decisions, enumeration is the relevant exact method when the list is a few hundred and the
forward model is cheap. For a future much larger graph catalog, use structural reductions, valid bounds
or hierarchical evaluation before stochastic search. The state of the art is matching computation to the
problem's structure, not maximizing the number of optimizer names.
For scarce measurements, selecting a few legal experiments that reveal parameter sensitivity or
separate graph hypotheses can be more valuable than adding random shots. D-optimal design is one
possible criterion, but it is model-dependent and can be poorly conditioned if all experiments probe the
same parameter combination. Include repeats and independent checks; never count samples within one
waveform as separate experiments. [W17]
What is not established by this research
No directly comparable public PowerNext participant implementation or complete judge scoring rubric
was located. No retrieved paper establishes that the repository's particular parallel-tail recipe is
authorized on CPRI hardware. No external method supplies missing real CPRI data. No research result
justifies claiming current conformity percentages as calibrated real-world pass probabilities.
13. Audit of the proposed revised
architecture
Verdict on the proposal
The proposal is a good scientific direction, but incomplete as a final architecture and
low-value if implemented only as an inactive residual placeholder. Its motivation is correct: the
simulator explains its declared circuit; measured discrepancy can supply information unavailable from
that simulator; the optimizer should coordinate legal settings and rank the active prediction. The right
next step is calibration-first and evidence-gated, with charge and uncertainty integrated into the
decision.
The proposal should not be rejected for being insufficiently ML-driven. There is no primary requirement
that ML must overrule an exact simulator trained into its own targets. It may be competitively
unconvincing if the team cannot show a useful ML function, however. The existing batch exploration and
exact organizer-method benchmark can supply that function honestly; a measured calibration
demonstration is stronger when genuinely applicable evidence exists.

Six corrections required
• Resolve model structure before fitting discrepancy. A residual may hide a wrong shunt location,
 basic-C double count or omitted branch. Establish the graph or a restricted effective model before
interpreting learned corrections.
• Calibrate a small identifiable parameter set first. Keep directly known components fixed,
 separate instrument calibration, inspect sensitivity/conditioning and validate across independent
settings.
• Move charge solving with prediction authority. If the calibrated predictor changes gain,
 recompute charge. If gain depends on charge or polarity, solve the bounded implicit problem rather
than assuming linear scaling.
• Keep waveform and metric authority consistent. A scalar correction does not automatically
 generate a corrected curve. Show nominal physics and corrected metric estimates separately unless a
validated reconstructed trajectory supplies both.
• Evaluate robustness at one actual setting. All uncertainty scenarios must share the selected legal
 charge. Retuning each scenario silently assumes information or control the engineer does not have.
• Promote only on independent decision evidence. A new upload can improve diagnosis
 immediately; it must not silently replace the serving model. Compare against calibrated physics alone,
maintain support/uncertainty gates and preserve rollback.

Authority hierarchy
Physical hardware constraints and model/evaluator applicability come first. A prediction cannot override
a missing component, excessive charge/energy, an unsupported nonlinear DUT, or unknown approved
wiring by receiving a favorable score.
Within a valid declared model domain, the active predictor is selected by evidence. Today that is nominal
physics. With appropriate identified measurements it may be calibrated physics. A hybrid residual
becomes active only when it improves held-out decisions beyond that calibrated baseline and passes
support/uncertainty checks. Operator approval remains a separate final act outside this PoC's authority.
Use four explicit labels: nominal-model conformity, calibrated predictive conformity, qualified
measured conformity for a specific shot, and operational approval. They answer different
questions. A measured historical pass cannot certify the next unperformed shot, and a calibrated
prediction cannot approve an unknown physical allocation.
Correct charge and robustness logic
For a linear active predictor, define k(c,θ) = Vcrest/q = Nη, the crest per unit per-stage charge; η =
Vcrest/(Nq) is the normalized voltage gain. Candidate c is robust over the tested scenario set only if there
exists one legal charge q satisfying every scenario:
0.97 Vtarget ≤ k(c,θ)q ≤ 1.03 Vtarget, for all tested θ.
Thus intersect all scenario charge intervals [0.97Vtarget/k(c,θ), 1.03Vtarget/k(c,θ)] with the legal charge
interval, then apply actual quantization. If the intersection is empty, the candidate is not robust at one
implementable setting, even if each scenario separately has some successful charge. Timing and
waveform validity must also pass for the same candidate/scenarios. This is a derived engineering
condition, not a statistical guarantee.
If calibrated gain depends on charge or polarity, use the complete active predictor in a bounded
one-dimensional solve and verify domain/monotonicity assumptions. Continue to enforce actual charge
tolerance and energy at the quantized setting. Reusing a normalized nominal trajectory is valid only for
the amplitude-linear portion of the model.
Ranking and uncertainty
Keep the current conformity-first J ranking as the default nominal objective. Add an explicitly named
alternative policy only when justified: for example, compare nominal best with the candidate having the
largest worst tested-scenario margin, or with the nearest practical passing change from current setup.
Display the tradeoff rather than hiding it in arbitrary new weights.
Uncertainty should initially be a named scenario envelope with its assumed inputs, plus an explicit
unquantified model-discrepancy limitation. With enough genuine data, report measurement uncertainty,
parameter uncertainty, repeatability and residual predictive uncertainty without double counting. If
claiming joint crest/front/tail coverage or performance after selecting the best of hundreds, validate the
actual joint/selection procedure. Ordinary marginal intervals are insufficient by themselves.

Behavior with and without measured data
Without genuine CPRI measurements, the calibration state is unfit; nominal physics remains active; the
current simulator surrogate remains synthetic; and uncertainty is conditional on declared assumptions.
No inactive zero residual should be advertised as learned adaptation.
With measurements, the software first verifies actual fired configuration, trace quality and measurement
chain. It compares before fitting, identifies a small parameter set, holds out independent
configurations/sessions and checks calibrated-physics performance. A residual is added only for
remaining systematic discrepancy that survives those controls. Promotion creates a new immutable
serving version, with rollback and a clear domain. Uncovered candidates are retained with the
appropriate baseline/uncertainty or an unresolved comparison.
16. Why ML belongs where it is placed
ML belongs where observations can improve a prediction or where approximation supplies a
demonstrated workflow benefit. In the present project, simulation-trained residuals can make a batch of
scalar scenarios cheaper to explore. They cannot improve the physical truth beyond the simulator
producing their labels. Giving them more authority would change the decision procedure without adding
the evidence needed to justify that change.
The strongest future role is learning repeatable setup-dependent departures from the nominal circuit.
Sometimes those departures are best represented by a few effective parameters; sometimes a small
remaining residual is useful. Both require measurements. A large direct inverse model would have to
learn nonunique settings, discrete availability, charge limits and no-solution behavior from sparse data,
while the existing optimizer already handles those explicitly.
This placement meets the literal PS's ML prediction requirement and gives a credible path to stronger
measured benefit. It does not pretend that the current optimal setting requires ML. If judges ask why AI is
necessary, answer the actual demonstrated function and the data-dependent next function. A
scientifically honest bounded role is stronger than an ML-controlled recommendation trained only to
mimic its own cheaper reference.
The current forward surrogate should remain only where its role is legible: fast supported scenario
batches, diagnostic comparison and model-method evidence. It should not run thousands of redundant
single-row calls merely to make the final optimizer appear ML-driven. Future empirical residuals should
be compared with a constant correction and calibrated physics; if the simpler model wins, deploy the
simpler model.
Small data favor low-dimensional residuals, interpretable parameter maps and carefully selected
experiments. Extra synthetic rows can improve surrogate coverage but cannot reduce the unknown
simulation-to-machine discrepancy. Neither transfer from the 3 µF workbook nor a low-voltage bench
residual automatically calibrates the 0.5 µF CPRI machine.

17. Why physics belongs where it is placed
Physics supplies the structure the available data cannot establish: energy and charge relationships,
circuit topology, discrete component consequences, amplitude scaling, coherent waveforms and
interpretable effects of load and inductance. It also provides an efficient reference across the complete
catalog.
Physics is not infallible. The current numerical solution is accurate for its declared graph, while the
graph's physical applicability is unresolved. The purpose of calibration is to improve predictive
correspondence, not to declare the nominal solver wrong whenever a real trace differs. The first
questions are whether the actual circuit, measurement plane and settings match, then whether a
bounded parameter correction explains the discrepancy.
Placing physics inside both candidate evaluation and calibrated prediction ensures the displayed
waveform and physical constraints remain coherent. It avoids fitting arbitrary scalar outputs that cannot
coexist in one waveform. A residual can still adjust expected measured metrics when validated, but must
not silently turn an unchanged nominal curve into a claimed calibrated trajectory.
The current model also makes a useful engineering explanation possible: charge mostly scales
amplitude; tail resistance strongly affects duration; front-path R/L/C affects rise; stage count changes
both initial voltage and effective storage. Those relationships are conditional on the circuit and should be
demonstrated with exact candidate comparisons rather than universal slogans.
Physics should become more complex only when evidence shows the simpler model fails for the intended
decision. Distributed stages, firing dynamics or specialized load networks belong in separate qualified
profiles when needed. Adding them speculatively before the finale would increase validation burden
without confirming the actual machine.
18. Why the optimizer belongs where it is
placed
The inverse problem has multiple feasible settings and discrete hardware choices. The optimizer is
therefore the natural coordinator: it constructs the allowed configuration space, solves charge, applies
constraints, obtains predictions, ranks alternatives and explains when the declared space contains no
passing answer.
Its authority concerns a decision under an explicit model and policy. It cannot make a provisional recipe
approved, substitute an assumed load for the requested load, or reinterpret model OOD as physical
impossibility. Keeping these responsibilities separate makes the system inspectable and prevents a
neural model from concealing constraint violations.
Exhaustive search is a strength at the current scale because it preserves every candidate and permits a
scoped completeness statement. It is not novel by itself, nor proof of a global optimum over all real Marx
arrangements. The current scalar charge solution and small dynamic model make exact enumeration a
suitable structural choice.
The final objective should reflect engineer value transparently. Waveform conformity remains
mandatory; among passing settings, the engineer may prefer waveform centering, larger tested margins,
fewer actual physical changes or lower energy. Show those alternatives and their tradeoffs. The existing
field-change count should not be promoted into a real labor-time estimate until actual module allocation
is known.
If future confirmed hardware creates a much larger graph space, the optimizer can use equivalence
classes, branch-and-bound or validated surrogate ordering while retaining correctness checks. That is a
future scalability decision, not an argument for stochastic search in a 504-entry problem.

19. Measured-data and calibration strategy
First establish an auditable observation
Each shot record should identify source domain, original export hash, date/session, machine/profile
revision, actual fired topology and component placements, N and charge, polarity, DUT/divider/stray
conditions, lead/return arrangement and acquisition settings. Preserve raw samples and explicit
voltage/time units, divider ratio, digitizer scaling, trigger/beginning definition, baseline treatment and
known instrument uncertainty. A user-entered “CPRI” label is not authentication.
Reject or quarantine clipped, truncated, nonmonotone-time, ambiguous-unit, inconsistent-polarity and
unsupported waveform records. Retain the reason and original bytes. Do not silently sort, filter, rescale or
relabel a trace to make it trainable. The existing importer already implements several of these good
controls; its qualification and export lifecycle need completion. [R16]
Where available, use the laboratory's qualified analyzer output and measurement-system identification
as the reference, with the local clean-trace evaluator remaining diagnostic until qualified. Instrument
response and correlated waveform uncertainty can materially affect derived metrics; treating all sample
errors as independent is not justified. [W22]
Staged calibration
Stage 0 is a before-fitting comparison using actual settings. Check units, polarity, timing origin, clipping,
wrong recipe and measurement-plane mismatch before attributing everything to physics. Record nominal
errors and an untouched baseline.
Stage 1 identifies the graph or narrows competing hypotheses. Use known connections, component
measurements and a few deliberately varied settings. If two graphs explain the same data, report that
ambiguity and choose an experiment that separates them; do not average them into a fictitious
approved circuit.
Stage 2 fits a small bounded effective parameter set. Candidate quantities include total output C, loop L
or R, or a separately justified scale factor. Do not fit DUT, divider and stray capacitance separately when
only their sum is observable. Do not let a free scale factor conceal an uncalibrated divider ratio. Inspect
parameter sensitivity, correlation, plausible ranges and fit stability.
Stage 3 validates calibrated physics on untouched configurations/sessions and relevant charge/polarity
domains. Repeated shots estimate variability; independent changed settings estimate generalization.
Dense samples from one shot do not increase the number of independent experiments.
Stage 4 considers a small residual only if calibrated physics retains a repeatable, decision-relevant bias.
Start with a constant or regularized low-dimensional log-ratio correction; use a small GP only if its extra
flexibility and uncertainty improve held-out results. Retain the simpler model if the residual adds no
measurable benefit.

22. Competitive differentiation analysis
Likely baseline, with explicit uncertainty
A plausible baseline team can train a regressor on the supplied workbook, accept target/load inputs,
predict waveform metrics, search or regress resistor settings and display a dashboard. Another team
may use approximate circuit formulas plus grid search. This is a reasoned benchmark class, not verified
knowledge of participants.
Features many teams can plausibly reproduce include a polished input form, waveform plot, model-count
comparison, a high pooled R², a PDF export and a chatbot explanation. These can help presentation but
do not establish better physical settings. Commercial laboratory systems already contain measurement,
analysis, history and reporting features. [W12]
Where this repository is stronger
The project has an explicit source hierarchy, later-clarification integration, full finite catalog, correct clean
LI construction, numerical checks across two graphs, grouped synthetic holdouts, OOD/abstention,
negative cases, immutable evidence, real model-serving routes and a developed offline application.
These are harder to reproduce well than a single spreadsheet model.
The strongest demonstration of those advantages is not a slide of test counts. It is a request whose result
can be defended: exact available parts, a coherent predicted waveform, individual margins, a reason why
the chosen row wins, a correct no-solution case and a preserved evidence record.
What a simpler team could do better
A team with the actual fired schematic and a few genuine held-out traces could have a more credible
physical model despite fewer modules. A team demonstrating a reliable first-shot setting or a clear
reduction in physical reconfiguration could beat a more elaborate synthetic-only system. A team with a
fast, uncluttered live interaction could look more useful if this app spends a minute on internal overhead.

24. Features not worth building
Do not build a PINN to solve the existing tiny linear circuit, a deep waveform generator without a
measured corpus, reinforcement learning to choose among a few hundred fixed candidates, a graph
neural network for an unconfirmed circuit family, or a generic LLM operator assistant that explains results
without improving their correctness.
Do not replace the exact current catalog search with GA, PSO or Bayesian optimization solely to appear
more advanced. A continuous optimizer can suggest unavailable parts; a stochastic discrete optimizer
can miss a narrow feasible set. Such methods become useful only when a confirmed larger problem
creates a real computational need.
Do not transfer the supplied 3 µF synthetic residual directly into the actual 0.5 µF machine and call it
calibration. Do not generate more “observed” rows from the same simulator and describe them as
empirical evidence. Do not train a classifier for faults without a qualified fault dataset.
Do not implement automatic continuous retraining on every uploaded trace. Upload quality, actual
setting, instrument state and model applicability must be reviewed. An archive can learn in the ordinary
sense of retaining evidence without automatically changing a validated serving model.
Do not build an expensive general topology editor or distributed spark-gap simulator before receiving the
actual fired circuit. A small correct profile is preferable to a general system whose physical assumptions
cannot be defended.
Do not spend the remaining time on new high-voltage hardware, automated firing, additional cloud
infrastructure, a second dashboard theme, or a physical bench rig requiring new procurement. The user
explicitly excludes high-voltage hardware. A low-voltage method demo is optional and must earn its time
through a repeatable result.
Do not add confidence percentages from model variance alone, or label corner sweeps as a guaranteed
continuous worst case. A transparent scenario range is more scientifically useful than a precise but
unsupported probability.

26. Low-voltage physical-demo verdict
Verdict: optional P2, worthwhile only when instruments and a repeatable fixture are already
available. Its purpose is to demonstrate the measurement-to-calibration-to-next-prediction method. It
cannot validate CPRI's megavolt topology, spark-gap erection, corona, insulation behavior or high-voltage
amplitude invariance. It should not displace physical-model clarification, exact-build verification or the
software rehearsal.
Simplest credible circuit
Use a separate low-voltage BENCH profile, not fake CPRI units or a bypass of the CPRI request limits. One
suitable illustrative circuit is a 5 V charged reservoir capacitor Cg = 1 µF, front resistor 330 Ω, output
capacitor CL = 100 nF and output-side tail resistor 4.7 kΩ. A break-before-make electronic switch
disconnects charging before releasing the pulse into the network. A low-voltage switch family with an
appropriate 5 V operating range is available in official component documentation; the exact component
and loading must be checked for the fixture. [W24]
The reservoir capacitor's initial pulse energy is ½ × 1 µF × 5² = 12.5 µJ; this does not include any
separate board or supply storage. The simple initial current bound through 330 Ω is about 15.2 mA. The
ideal RC model predicts crest about 4.179 V, an LI-style virtual front about 84.7 µs and tail about 3.987
ms from that virtual origin, or about 3.971 ms from switch closure. These are independent model
calculations, not measured hardware results. The circuit is deliberately at an accessible voltage and time
scale. [R20]
Manufacturer material also describes a single-stage low-voltage impulse model for studying or
preselecting impulse parameters, supporting the educational mapping. That does not make a bench
fixture a scale-validated substitute for CPRI's generator. [W23]
What to measure and show
Capture the actual output voltage with a known oscilloscope/probe input, adequate sample rate to
resolve the front, a sufficiently long record for the tail, pretrigger baseline and explicit time/voltage
scaling. A roughly 1 MS/s or faster acquisition would give useful front sampling for the illustrative
tens-of-microseconds pulse, subject to instrument bandwidth, record length and actual waveform.
Include enough tail duration and repeat captures to reveal repeatability.
Measure or document actual resistor/capacitor values and probe loading. Use several distinct allowed
bench settings for fitting a small effective parameter, with at least one genuinely untouched setting for
prediction. The exact number is an experimental design choice for this method demonstration, not a
general calibration sufficiency claim.
The compelling sequence is: predict a bench waveform; capture an actual trace; show a systematic
mismatch under actual settings; fit one justified effective parameter using designated training traces;
predict a held-out trace; then show the next allowed bench setting and its measured result. Report

Hard questions: concise answer, technical depth, follow-up and danger
Q1. What exactly did CPRI ask you to solve?
Competition answer: We help an engineer select active stages, per-stage charge and available
front/tail resistors for a requested LI or SI waveform under a declared test setup. We predict waveform
parameters, check the specified limits and rank alternatives before physical trials.
Technical answer: The PS combines engineering calculations, trained settings-to-waveform ML,
constrained recommendation and visualization. The variable load includes DUT, measurement and stray
capacitance plus arrangement-dependent effects. The goal is a reliable starting point that reduces setup
iteration; actual trial reduction requires measurement. [R01–R05]
Likely follow-up: How have you measured that reduction?
Dangerous answer: “Our synthetic accuracy proves fewer real CPRI shots.”
Q2. Which generator are you modeling, and why do the supplied files disagree?
Competition answer: The later CPRI clarification establishes 15 stages, 200 kV per stage, 0.5 µF per
stage and 150 kJ total at full charge. We use those machine facts. The original illustrative nameplate and
3 µF synthetic workbook are separate sources.
Technical answer: Stage energy is ½Csq² = 10 kJ at 200 kV, so 15 stages give 150 kJ. The PS figure
helps describe parameter categories but is superseded for actual ratings. The workbook remains useful
for method reproduction within its own domain. [R01–R06]
Likely follow-up: Which source confirms the resistor placements?
Dangerous answer: “Every supplied document describes the same physical generator.”
Q3. Are all 504 configurations actually legal on our machine?
Competition answer: They exhaust the declared uniform-recipe catalog for one mode and topology.
The six component values are confirmed; complete placements, quantities and approvals are not. We
therefore label these as conditional numerical configurations.
Technical answer: The count is 14 stage counts times six front choices times six tail choices. Optional
LI parallel tails add 84. A value inventory does not establish per-stage quantity sufficiency, pulse ratings
or socket allocation. Approved scope currently has zero recipes. [R04, R08, R14]
Likely follow-up: What information would make a result operationally usable?
Dangerous answer: “Exhaustive means every possible real Marx connection.”
Q4. What exactly does your ML learn?

hypotheses.
Technical answer: The target transformation is log(simulated target / analytic baseline). The features
include settings, reduced circuit values, ratios and analytic outputs; amplitude is factored out under the
declared linear model. These are synthetic simulator-emulation models, not measured CPRI calibration.

demonstration. It has substantive code, correct declared-circuit mathematics, complete scoped search,

The conditions are precise: the actual presentation package must be verified and rehearsed;
source/model/runtime identity must be clear; physical recipe assumptions and synthetic data must
remain visible; current calibration/measurement qualification must be described accurately; and the
demonstrated UI/export inconsistencies must be fixed or explicitly excluded from claims.
It is NOT READY for operational CPRI hardware instructions, certified measured-waveform
compliance, calibrated real-machine uncertainty, or claims of reduced real trial shots. Those
require confirmed physical connections and applicable measurement evidence. This boundary does not
make the software PoC worthless or noncompliant with the later conditional measured-data guidance.
What could upgrade the verdict
A confirmed fired circuit and allowed BOM would substantially improve physical applicability even before
a new model is trained. A small set of well-documented anchor shots with independent checks could
establish a restricted measured validity domain. A calibrated-physics or residual model that improves
held-out decisions could then gain scoped authority. Complete instrument/evaluator qualification and
wider operating evidence would be needed for stronger deployment claims.
The immediate competition goal is to make the conditional PoC maximally useful and defensible. That
means demonstrating a correct decision, its reason, its limitations and the next useful action on an exact
reproducible build. It does not require finishing the entire post-competition calibration architecture before
the finale.
What could downgrade the verdict
The project should be treated as not ready for presentation if the exact package cannot launch/reproduce
its key cases on the actual laptop; if an unconfirmed parallel recipe is presented as approved; if synthetic
metrics are sold as real CPRI accuracy; or if a demonstration depends on a newly added unverified
calibration/pruning mechanism. These are avoidable failures of readiness or claim discipline.
